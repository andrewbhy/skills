# jig-typescript

Start: run `node "${CLAUDE_PLUGIN_ROOT}/skills/jig-typescript/telemetry.mjs" start "<project-root>" <provider>`; retain the printed run ID (`off` means disabled).

1. **Read the project.** Read applicable rules and ADRs, then the project's stated contract in its README, task and tests. Before changing code, list each rule those sources state, with its source and expected observable result, and run the project's tests to record the baseline, including existing failures. Turn any stated contract without an existing test into a test through the public entry point; run it before implementing the change so a broken contract is an observed failure. Find the project's test, type-check, full Biome check (linter and formatter), boundary and dead-code commands in its scripts or small project configuration. Keep module paths, runtime targets, entry points and commands there. Reuse existing tools before adding dependencies. Use [starter/](starter/) only when configuration is missing: copy `tsconfig.starter.json` and `biome.starter.json` to the project root without `.starter`, and adapt them to the runtime rather than overwriting established configuration.
2. **Make types enforce the contract.** Run the exact pinned TypeScript 7 compiler with `strict`, `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`. Forbid `any`, unchecked casts and non-null assertions with Biome `noExplicitAny`, `noUnsafeTypeAssertion` and `noNonNullAssertion`. Prefer `unknown`, narrowing, discriminated unions and `satisfies`; do not silence errors with assertions, suppressions or weaker compiler options.
3. **Parse once at entry.** Treat network, files, environment, storage and third-party results as unknown. Parse and validate them at the trust boundary with an existing schema parser or a small checked parser; derive types from the schema rather than maintaining two shapes. Test malformed input there. Trust the resulting internal contract: remove defensive catches and null checks inside it. Keep checks for absence that the domain actually permits. Biome `noUselessCatch` catches redundant rethrows; review must catch swallowed errors, redundant validation and missing boundaries.
4. **Own asynchronous work.** Await or return promises; give deliberately detached work an explicit error handler and lifetime owner. Enable Biome `noFloatingPromises` and `noMisusedPromises` as errors. Where compiler-based analysis is needed, use pinned Oxlint with its matching `oxlint-tsgolint` and `--type-aware`; do not force incompatible peer dependencies. Propagate cancellation through an `AbortSignal`, stop owned work on cancellation, and handle errors where recovery or translation belongs. Test rejection and cancellation; review ownership and swallowed failures. A `void` prefix alone does not handle an error.
5. **Keep one structure.** Enforce module entry points, layers, forbidden edges and cycles with dependency-cruiser rules in the project, run alongside the type check. Use Biome `noRestrictedImports` for simple import bans. Prove a forbidden import fails; an empty boundary configuration proves nothing. Give each state, schema and policy one owner; review duplication and dependency direction across the application. Delete superseded implementations and compatibility shims with their callers. Use TypeScript unused-local checks and Biome `noUnusedVariables`/`noUnusedImports`; use Knip with real entry points for unused exports, files and dependencies. Do not treat a public package export as dead merely because it has no local caller.
6. **Keep dependencies small and prove the result.** Prefer platform APIs; justify each addition by maintenance, licence, size and transitive cost. Pin exact direct versions, retain the lockfile and use `npm ci` (or the existing lockfile's frozen install); check manifests for ranges and lockfile drift in CI. After changing code, rerun the project's tests, including the contract tests, and compare with the baseline. Run type check, the full Biome check including the formatter (`biome check`, not lint alone), boundary and dead-code checks plus relevant behavioural tests. Keep both the linter and formatter enabled. Check every listed contract rule through the public entry point as a caller would, including valid input, invalid input and stated edge cases; report the result for each rule and any untested rule. Report which rules each tool actually caught and which need review. Do not call a green type check proof against explicit `any`, casts, floating promises or unused exports. See [starter/README.md](starter/README.md) for tool limits. Report unavailable checks and provider scenarios as not tested; grant no merge approval.

End: run `node "${CLAUDE_PLUGIN_ROOT}/skills/jig-typescript/telemetry.mjs" end "<project-root>" <provider> <run-id> <passed|failed|stopped|partly>` before reporting; disclose marker failures.
